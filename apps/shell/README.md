# VRMXG shell

M1 W0 (AB-T-0512). The shared Mac shell every VRMXG app runs in (AB-D-0253): a sandboxed `WKWebView` around the app's
web build, a typed native bridge, file and project panels, and standard menus. A Swift package; apps are small
executable packages on top of it, built with SwiftPM (no Xcode project).

```swift
import VRMXGShell
ShellApp.run(ShellConfiguration(appName: "VRMXG Playground", scheme: "vrmxg-playground",
                                methods: [("app.hello", { p in ["hello": p.string("name") ?? "world"] })]))
```

```js
import { inShell, call, on, onClosing } from '../../shell/js/shell.js';
if (inShell) {
  const info = await call('shell.info');                       // { shell, app, appVersion, origin, url, methods }
  const f = await call('file.open', { types: ['vrmxs'] });      // { path, name, size, text }
  await call('file.save', { text, suggestedName: 'cafe.vrmxs' }); // { path, name, bytes }
  on('menu.save', save);                                        // File menu commands arrive as events
  onClosing(async (reason) => await askAboutUnsavedWork());     // before the window closes or the app quits: true goes on
}
```

| Piece | What |
|---|---|
| Origins | The web build (`Resources/web`) over a loopback HTTP server, the default (a 20 µs timer and SharedArrayBuffer, AB-L-0346), or the custom scheme `<scheme>://app/` (`VRMXG_ORIGIN=scheme`). `VRMXG_QUERY` adds a query string. Both send the cross-origin isolation headers |
| Project mount | `project.open` mounts a folder at `/project/` on both origins, so the page fetches project assets by URL. With none mounted, `/project/` is the web content's own `project/` folder (shell 0.11.0, M5 W1): where a game build keeps its files when the build is the app's web content (`apps/game-mac`) |
| Bridge | `window.webkit.messageHandlers.vrmxg.postMessage({ method, params })` returns a promise (`WKScriptMessageHandlerWithReply`); errors come back as `{ code, message }` (`bad_request`, `unknown_method`, `bad_params`, `cancelled`, `no_project`, `failed`). Native → page: `vrmxg-shell` events |
| Methods | `shell.info` (with the `scheme` base); `file.open`, `file.save` (system panels; writing back to a file the person opened or saved needs no panel; `text`, or `base64` for binary); for a binary file the person picks (a `.vrmxa`, AB-A-0314, shell 0.6.0), `file.open { types, serve: true }` serves it at `url` (`/opened/<token>/<name>`, on both origins, no copy over the bridge) and `binary: true` returns `base64` instead (≤ 64 MB); `remember: "<key>"` keeps a security-scoped bookmark, so `file.reopen { key, serve? }` opens it on a later launch with no panel (null when nothing is remembered or the file has gone) and `file.forget { key }` drops it (the app needs `com.apple.security.files.bookmarks.app-scope`); `project.open`, `project.list`, `project.write` (`text` or `base64`); `build.begin { name }` → `{ id, path, name }`, `build.write { id, path, text | base64, offset? }`, `build.end { id }`, `build.abort { id }` (shell 0.10.0, M5 W0, AB-T-0615, `BuildFolder.swift`: a game build written into a folder the person picks, for the editor's Export Game. The files are staged inside the folder (`.vrmxg-export-<id>`), so a failed, aborted or abandoned export leaves the folder as it was; `id` is the page's handle on its export, and `offset` is where a piece of a file begins, so no message has to hold a whole one and a piece sent twice is refused. `build.end` checks every staged file against the staged manifest (size and SHA-256, hashed natively), then holds the earlier build's files aside, puts the new manifest over the old and moves the new files in; if a step fails the earlier build is put back, so the folder holds one build or the other, never neither (a file that can't be put back stays held in the staging folder, which is then kept and named in the error, for the next export to restore). The folder may be absent, empty or hold an earlier build, every file in it one that build's manifest lists; it is refused before anything is touched when it holds any other file, a symbolic link anywhere, or a manifest of a version the shell doesn't read. Only the folder's own manifest says what a build wrote: a leftover staging folder is removed and licenses nothing outside it, and no build path may begin with `.vrmxg-export`. These four methods, `VRMXG_SHELL_BUILD` and `project.open`'s `truncated` are what 0.10.0 adds to 0.9.0: nothing an app already calls changes, and a page can also find the methods in `shell.info`'s `methods`); `project.open`'s answer also says `truncated` when the project has more files than the listing holds (20,000); `settings.read` → `{ text, path }`, `settings.write { text }` (shell 0.11.0, M5 W1: one settings document in the app's own folder, `Application Support/<bundle id>/settings.json`, written atomically, at most 256 KiB; `VRMXG_SHELL_SETTINGS` moves it. A page's own storage can't hold settings in a Mac app: the loopback origin's port changes every launch); `app.quit` (shell 0.11.0: the page quits the app, as the menu's Quit does, so an app that asks its page before quitting still asks); `saves.list`, `saves.read`, `saves.write`, `saves.remove` (save slots in the app's own folder, Application Support/<bundle id>/Saves, no panels; `VRMXG_SHELL_SAVES` moves it; shell 0.3.0, M2 W9; the delegate keeps the `SaveMethods` for the app's life, since its handlers capture it unowned: a temporary crashed the first call, 0.4.0); `export.begin`, `export.end`, `export.cancel` (frame export, below); `camera.status`, `camera.devices`, `camera.start { fps, device?, face? }`, `camera.stop` (M3 W5, shell 0.5.0: AVCapture and Vision on a background queue, feature frames to the page as `camera.frame` events, never an image; the app needs `com.apple.security.device.camera` and NSCameraUsageDescription, or camera.start refuses; spike-camera/README.md has the verdict. `face: true` (shell 0.8.0, M4 W9: face takes) adds the face's shape from Vision's landmarks to each frame, `face.shape { blinkL, blinkR, jaw, smile, browUp, browDown, yaw, pitch, roll, geo }`, measured by `FaceShape.swift` and tested on drawn faces; spike-face/README.md has that verdict); `microphone.status`, `microphone.request` (M3 W3, shell 0.6.0: the permission the page's getUserMedia and a native capture path share; the app needs `com.apple.security.device.audio-input` and NSMicrophoneUsageDescription, or microphone.request refuses; the web view's getUserMedia is granted for the app's own origins only and only for the devices the app declares); `window.show`, `window.hide`, `window.state`, `window.setMode { mode: "normal" | "floating", size?, borderless? }` (AB-A-0317, shell 0.6.0: floating stays above other apps on every Space at its own saved frame, 360 × 480 the first time; borderless drops the title bar and background so only the page draws; `window.state` events `{ visible, mode, key }` on show, hide, minimise and occlusion, so the page can drop its frame rate); plus each app's own |
| Voice (optional) | [`Voice/`](Voice/README.md), its own package (M3 W3, AB-T-0542): `tts.speak`, `llm.respond`, `stt.transcribe`, `stt.listen` / `stt.stop` and `voice.*` on an in-process MLXEngine (Kokoro, Qwen3.5-4B, Nemotron, VoiceChatKit's VoiceListening). An app adds it with `ShellConfiguration(setUp: VoiceMethods.mlx)`, or `VoiceMethods.mlx(parts: [.tts])` to speak only (the creator, AB-T-0614); `setUp` (shell 0.6.0) is how any optional product registers methods and keeps itself alive (`keepAlive`) |
| Binary POSTs | `PostRouter`, on both origins: the page `fetch`es an `ArrayBuffer` or typed-array body (a `Blob` body arrives empty; typed arrays don't cross `postMessage`, spike-frame-export); the reply comes once the body is consumed, which is the backpressure. Responses carry CORS headers, so a loopback page can POST to the scheme (the faster transport) |
| Frame export (M1 W8) | `export.begin { width, height, fps: [num, den], frames, codec, audio, hash, suggestedName }` opens the file (save panel, a granted `path`, or `VRMXG_SHELL_EXPORT`: a file, or a folder ending in `/`); `POST __export/frame?id=&n=` raw RGBA from `readPixels`, flipped and swizzled with vImage and appended to AVAssetWriter (H.264 / HEVC with B-frames and BT.709 tags, HEVC with alpha, ProRes 4444 un-premultiplied), frame n stamped n · den / num; `POST __export/audio?id=` the mixed WAV, muxed as AAC after the last frame (passthrough video, so the writer's interleaving never waits on sound); `export.end` returns the file and timings. With `hash: true` it also returns each frame's hash as it arrived, using the page's own `hashFrame` (FNV-1a in two lanes, so a shell hash and a page hash of the same pixels are equal; shell 0.4.0, M2 W12). With `subtitles` (SRT text) on `export.begin`, it writes `<name>.srt` beside the movie. It writes directly where it can; in the sandbox it writes as a related item, through an `NSFilePresenter` and the app's `NSIsRelatedItemType` document type for srt. Automated exports keep `<file>.frames.json` and the WAV beside the file |
| Menu bar apps (AB-A-0317) | Opt-in through `ShellConfiguration`, so other apps don't change: `statusItem: StatusItemConfiguration(symbol:, items: [(title, event)])` puts an icon in the menu bar with Show / Hide Window, the app's items (as `menu.<event>` events) and Quit; `closeKeepsRunning: true` makes closing hide the window and keeps the app running; `dockIcon: false` runs it as an accessory app (no Dock icon, like LSUIElement) |
| Menus | App, File (Open…, Open Project…, Save, Save As…: sent to the page as `menu.*` events), Edit (undo / redo and the clipboard through the responder chain; with `pageUndo`, undo and redo go to the page as `menu.undo` / `menu.redo`), View (Reload), Window. An app adds its own (shell 0.7.0, M4 W5): `fileItems: [ShellMenuItem("New Short", event: "newShort", key: "n"), .separator, …]` after Open Project…, and `menus: [ShellMenu("Short", [...])]` between View and Window; each item sends the page `menu.<event>`. Apps that add none keep the menus as they were |
| Closing and quitting (shell 0.9.0, AB-T-0593) | Only for an app that sets `asksBeforeClosing: true`: File › Close Window, the close button and Quit (the menu, ⌘Q, the Dock, log out) ask the page before they act, so it can show its unsaved-changes sheet. The page hears `window.closing { id, reason: "close" \| "quit" }` and answers with `window.closeReply { id, answer }` → `{ pending }`: `"wait"` (it heard, and is asking the person: the shell then waits as long as the person takes), `"close"` (go on: nothing unsaved, or Save saved, or Don't Save) or `"cancel"` (keep the window and the app). `shell.js`'s `onClosing(decide)` does all of that: `decide(reason)` resolves to true to go on. A quit waits as `.terminateLater`, so a log out waits for the answer too. **The page also says whether it holds unsaved work**: `window.setEdited { edited }` (`shell.js`: `setEdited(bool)`, sent only when it changes) sets the dot in the close button and is what the shell goes by when the page can't answer. **A page that isn't answering** (nothing within `closeTimeout` seconds, 5; or, while it is asking the person, two of the shell's checks of its JavaScript in a row with no reply): with nothing unsaved the shell goes on, so a hung page can't block quitting; with unsaved work it asks the person in an alert of its own, Wait (the page is asked again) or Close Anyway, so a page that is only busy (a world being built, an export frame) never loses work without a question. **A question that never ends**: asking again while the page's question is up (⌘W or ⌘Q a second time; Quit goes through the shell for that, since AppKit takes no second quit while one waits) brings the same alert with Go Back or Close Anyway, so the person always has a way out. Asking again before the page has answered sends the question again; a quit that arrives then turns the question into a quit. A page that reloads, or whose process ends, with a question open has nothing left to save: the shell goes on. `kill` (SIGTERM) ends the app at once as before: it isn't a quit, and nothing is asked. Nothing is asked before the page has loaded, with `closeKeepsRunning` on a close (it only hides the window; the quit still asks), or for the quit that follows closing the last window (the page already said to go on). An app without `asksBeforeClosing` closes and quits without consulting the page, as before, and has neither method. **What the page owes**: every `decide` must resolve (one question at a time in the window: `@vrmxg/editor-ui`'s `questions`), and a document is marked saved only once its write has succeeded, or a failed Save makes the next close silent |
| Open Documents (shell 0.7.0) | Only for an app that names `openTypes: ["fountain", …]`: a file of those types that the Finder, `open` or AppProbe's `open` step hands it is served as `file.open { serve: true }` serves one, and the page hears `file.opened { path, name, size, url }`. Files that arrive while the page loads or reloads (a crash-reload too) wait for it; other types are refused and never granted. An app without `openTypes` doesn't answer Open Documents at all (`responds(to:)`), so AppKit says it can't open them, as before. The app's Info.plist declares the types it opens |
| Sandbox | `app-sandbox`, `network.client`, `network.server` (loopback), `files.user-selected.read-write` (panels) |
| Permissions (camera, microphone) | macOS judges a request by the app's *responsible process*. Launched by LaunchServices (Finder, the Dock, `open`), that's the app, and macOS asks the person once. Started as another process's child (AppProbe's `launch`, a terminal running the binary), it's the parent: the app silently gets the parent's answer, refused with no prompt if the parent was never granted (AB-L-0370), or "authorized" if the parent was. To check a permission, launch with `open -n --env VRMXG_SHELL_MIC=request --stdout <log> <app>`: the shell prints the microphone status before and after asking. Measured 2026-11-19 on the playground: a child of a granted parent shows `authorized` with no prompt; through `open`, `notDetermined` → the prompt → `authorized` |
| Automation | `VRMXG_SHELL_OPEN`, `VRMXG_SHELL_SAVE`, `VRMXG_SHELL_PROJECT`, `VRMXG_SHELL_EXPORT`, `VRMXG_SHELL_BUILD` (a build's folder, or with a trailing `/` a folder of builds named by `build.begin`'s `name`) stand in for the panels (relative paths are under the app's temporary folder, inside its sandbox), so AppProbe scenarios open and save without the panel |
